AutoCare

AI-Powered Semantic FAQ Chatbot for Maruti Suzuki 🇮🇳

Enterprise-grade customer support automation with semantic search, real-time FAQ matching, intelligent department routing, and admin knowledge management — built without heavy ML frameworks.

⚠️ Problem Statement

Maruti Suzuki dealerships and customer care teams handle thousands of repetitive queries daily — warranty coverage, service bookings, spare parts availability, insurance claims. Manual responses are slow, inconsistent, and don't scale.

Existing keyword-based chatbots fail on paraphrased questions. A customer asking How long is my car covered? gets no match for the FAQ What is the warranty period? because the words don't overlap.

💡 Solution

AutoCare uses semantic vector similarity instead of keyword matching. Every FAQ question is encoded into a 384-dimensional embedding using FastEmbed's ONNX runtime. User queries are encoded the same way and compared using cosine similarity — meaning paraphrases, synonyms, and natural language all work.

💡 Why FastEmbed over PyTorch?
FastEmbed uses ONNX Runtime (~100MB RAM) instead of PyTorch (~500MB+). Same model quality, 5x lighter footprint. Ideal for free-tier hosting like Render.

⚠️ First Run
The first startup downloads the ONNX model (~90MB) from Hugging Face Hub. This takes 30-60 seconds. Subsequent starts use the cached model.

🔄 Data Flow

1. User submits a query

Customer types a natural language question in the chat interface. The frontend sends a POST /chat request.

2. Query is encoded

FastEmbed converts the query into a 384-dimensional vector using the all-MiniLM-L6-v2 ONNX model.

3. Cosine similarity search

The query vector is compared against all pre-computed FAQ embeddings using NumPy dot product. The highest scoring match is identified.

4. Confidence check

If the best match score ≥ 0.45, the FAQ answer is returned. Below 0.45, a fallback message is sent and the query is logged as unanswered.

5. Gap analytics

Unanswered queries and negative feedback are logged for admin review. Admins can add missing Q&A pairs to close gaps.

🔒 Security

Admin endpoints are protected with Bearer token authentication. The default development key is:

text
admin-secret-key

To set a custom key, create a .env file in the project root:

env
API_KEY=your-secure-key-here

CORS is configured to allow all origins (*) for development. Restrict this in production.

❓ FAQ

How does semantic matching work?▼

User queries and FAQ questions are encoded into 384-dimensional vectors using the all-MiniLM-L6-v2 model. Cosine similarity between vectors determines the best match. This captures meaning, not just keywords.

What happens when a query has no good match?▼

If the confidence score is below 0.45, a fallback message is returned and the query is logged to unanswered_queries.log for admin review. Admins can then add the missing FAQ.

Can I add new FAQs without restarting the server?▼

Yes. The POST /api/qa endpoint adds new pairs and re-indexes embeddings dynamically. No server restart needed. Same for PDF uploads.

Why not use an LLM like GPT for answers?▼

AutoCare is a retrieval-based system by design. It returns verified, pre-written answers — no hallucination risk. For customer support in automotive, accuracy and consistency are more important than generative flexibility.

What PDF formats are supported?▼

Text-based PDFs with Q:/A: tags or question-mark-terminated lines work best. Scanned PDFs (image-only) and complex table layouts are not reliably extracted.
